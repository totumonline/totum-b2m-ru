# CSS

## Общие правила стилей
- Все названия CSS-классов пишутся через дефис - или двойной дефис --
- camelCase или snake_case не применяются
- Исключение: в дополнительных классах с префиксом `__` слова разделяются через `_`
    - `__zero_d`, а не `__zero-d`

## CSS transition при появлении элемента
- Если `requestAnimationFrame` нужен только для запуска CSS transition при первом появлении элемента в DOM или выходе из `display: none`, стараться использовать `@starting-style` вместо rAF.
- `@starting-style` вкладывать в правило элемента, для которого задаётся конечное состояние, а не выносить в отдельный блок с повторным селектором.

## Базовые стили
- Общие, переиспользуемые стили именуются просто:
  - `catalog-button`
  - `input-field`
  - `modal-header`

## Специфические стили (локальные)
- Если стиль используется только в одном конкретном месте, его имя — полный путь вложенности
- Уровни разделяются через `--`
    - `header--main--logo`
    - `header--main--actions--comparison`
    - `header--top-menu--contacts--dropdown--additional-contacts`

## Несколько классов для элемента только в двух случаях
- Требуется отметить динамический элемент
    -  `expandable __submenu`
- Необходимо отметить элемент большей спецефичностью и это не получается сделать одним селектором
    -  `header--main--catalog--search __clear`
    - В этом случае дополнительный стиль отмечается как `__`

## Когда путь в стиле становятся слишком длинным, то он разрывается в логически подходящем месте, например от dropdown
- Разрыв обозначается `---`
- `header--main--catalog--menu--dropdown---content` сокращается как `---content`
- `header--main--catalog--menu--dropdown---content--left` сокращается как `---content--left`

## Всегда стоит стремится использовать для элемента только один стиль!
- Дополнительный стиль `__some-stile` используется только если нельзя обойтись без повышения специфичности для избежания применения `!important` (надо всячески избегать `!important`)
- Или для обозначения элемента как активного или еще каким-образом динамически отмеченного, в этом случае используется дополнительный стиль `__some-additional-stile`

## При формировании структуры CSS необходимо избегать объединения стилей через `,`
- А также категорически запрещено в разных блоках назначать свойства: `.some-style {padding: 10px;} .some-style {margin: 10px;}`
- Один стиль у элемента в html, одна запись в css: `.some-style {padding: 10px; margin: 10px;}`

## ul, li и a по возможности без стилей (помимо дополнительных динамических `__active` и прочих подобных)
- Стиль назначается `div` в который помещены `ul` и `li` элементы
- Необходимо избегать назначения `.some-style > ul > li` селектор для `ul` будет `.some-style ul` а для `li` — `.some-style li`

## span использоватся только если в этом месте нельзя использовать div!

## Вместо wraper используется --block и он вне иерархии
- `.some-style--block` и внутри `.some-style--title` и `.some-style--text`

## Всячески стараемся избежать использования margin
- Структура дизайна строится на `display: flex` с `gap`
- Использование `flex` приоритетно над `grid`.
- `grid` используется, когда необходимо точнее управлять количеством колонок ии их пропорцями.

## Блоки CSS отделяются комментариями

- /* ########## SCROLLER ########## */

- /* ########## SCROLLER -- CONTENT ########## */

- @media (hover: hover) и @keyframes ставятся рядом с элементом к которому они относятся

- @media (max-width: 800px) медиа по ширине всегда ставятся в конце блока перед следующим /* ########## TITLE ########## */

## hover стили всегда оборачиваются в @media (hover: hover)

## Статический Brotli
- После изменения CSS необходимо создавать или обновлять для него статический Brotli-файл `.br`.
- Для `main.css` выполнять из корня проекта `/home/totum/totum-pro`:
  - `brotli -q 11 -k -f interfaces/b2m/public/css/main.css`

# JS

- Исходные JS-файлы находятся в `b2m/js`.
- При изменении JS необходимо через `esbuild` создавать минифицированные версии в `b2m/public/js`.
- Сборка только через `esbuild --minify`, сразу в итоговый файл, без промежуточных файлов и дополнительных проверок:
    - `esbuild interfaces/b2m/js/cart.js --minify --outfile=interfaces/b2m/public/js/cart.min.js`
- После сборки минифицированного JS необходимо создавать или обновлять для него статический Brotli-файл `.br`.
- Для `cart.min.js` выполнять из корня проекта `/home/totum/totum-pro`:
  - `brotli -q 11 -k -f interfaces/b2m/public/js/cart.min.js`
